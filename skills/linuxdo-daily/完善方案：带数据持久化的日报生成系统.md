## 双数据源策略

```
┌─────────────────────────────────────┐
│  Source A: #人工智能 标签             │
│  → /tag/444.json                    │
│  → 抓取 2-3 页                      │
│  → 标记 source: "ai_tag"            │
└──────────────┬──────────────────────┘
               │
               ▼
         合并去重（按 post id）
               ▲
               │
┌──────────────┴──────────────────────┐
│  Source B: 前沿快讯 分类              │
│  → /c/news/34.json                  │
│  → 抓取 2-3 页                      │
│  → 过滤 tags 含 "人工智能"            │
│  → 标记 source: "news_category"     │
└─────────────────────────────────────┘
```

### 为什么要两个源？

| 场景 | 说明 |
|------|------|
| `ai_tag` 独有 | 标签页可能有非"前沿快讯"分类的 AI 帖子 |
| `news_category` 独有 | 前沿快讯中可能有带 #人工智能 但排序靠后、标签页未显示的帖子 |
| 两者共有 | 高热度帖子，两个入口都能看到 |

两个源合并后**覆盖率更高**，不会遗漏。

## 抓取流程

### 方案一：Playwright MCP（需登录帖子）

```
Step 1: 打开页面
  playwright_navigate → https://linux.do/c/news/34

Step 2: 截图确认登录状态
  playwright_screenshot
  → 未登录？提示用户手动登录

Step 3: 执行 JS 抓取列表页数据
  playwright_evaluate → (() => {
    // 抓取所有帖子的基础信息
    // title, href, tags, views, likes, replies, time
    return JSON.stringify(posts)
  })()

Step 4: 翻页（重复 Step 3）
  playwright_click → .next-page
  → 通常抓 2-3 页（60-90 条）足够

Step 5: 过滤 #人工智能 标签
  在 JS 中直接过滤 tags 含 "人工智能"

Step 6: 进入详情页抓取正文（高价值帖子）
  对 like_count > 10 的帖子：
  playwright_navigate → /t/{id}
  playwright_evaluate → 抓取 .cooked 首帖正文

Step 7: 合并与持久化
  - 读取 data/posts/{id}.json（如存在）
  - 更新 scrape_history（追加本次指标）
  - 写入 data/daily/{date}.json
  - 写入 data/posts/{id}.json

Step 8: 生成日报
  - 读取当日数据
  - 按 tags 聚类
  - LLM 生成摘要和趋势分析
  - 输出 data/reports/{date}.md
```

### 方案二：JSON API（公开帖子）

```bash
# Source A
curl -s -k "https://linux.do/tag/444.json?page=0"
curl -s -k "https://linux.do/tag/444.json?page=1"

# Source B
curl -s -k "https://linux.do/c/news/34.json?page=0"
curl -s -k "https://linux.do/c/news/34.json?page=1"
```

linux.do 是 Discourse 论坛，公开帖子可通过 JSON API 直接获取。需登录帖子需用 Playwright 方案补充。

## 增量更新逻辑

```python
existing = read_post(id)

if existing:
    # 追加抓取历史
    existing["scrape_history"].append({
        "scraped_at": now,
        "views": new_views,
        "like_count": new_likes,
        "posts_count": new_replies
    })
    # 更新当前值
    existing["views"] = new_views
    existing["like_count"] = new_likes
    existing["posts_count"] = new_replies
else:
    # 新帖子，完整写入
    save_post({**new_data, "scrape_history": [{"scraped_at": now, ...}]})
```

每次抓取都能追踪帖子的**热度变化趋势**。

## Skill 使用方式

```bash
# 默认抓取（每源3页）
python3 skills/linuxdo-daily/scripts/scrape.py

# 自定义页数
python3 skills/linuxdo-daily/scripts/scrape.py --pages 5

# 抓取高赞帖正文
python3 skills/linuxdo-daily/scripts/scrape.py --detail
```

**输出文件：**
- `data/daily/{date}.json` — 当日原始数据
- `data/posts/{id}.json` — 帖子历史（含 scrape_history）
- `data/reports/{date}.md` — Markdown 日报

## 注意事项

| 问题 | 方案 |
|------|------|
| Cloudflare 挑战 | 有头浏览器 + 用户手动过验证 |
| 需要登录 | 浏览器保持登录态，用户手动操作 |
| SSL 证书问题 | `curl -k` 跳过验证 |
| 帖子太多 | 先抓 2-3 页，高 like 帖子优先 |
| 反爬检测 | Playwright 模拟真实浏览器，风险低 |
| 数据持久化 | 每条帖子独立文件，scrape_history 追加记录 |
