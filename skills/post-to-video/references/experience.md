## 一、封面与配图

### 🔴 封面文字源拆分：发布标题不进画面（v3.35.0 / 2026-09-17，坑 203）
封面画面文字的单一事实源是「封面大字」字段（Hook 原词短句：1 句冲突 + 1 个数字，两行排版），**禁止**把整条发布标题印上画面——堆叠会稀释冲突、与 Hook 脱钩。
**Hook/封面大字定稿必须早于封面生成**；改 Hook 必须删旧封面按新大字重出，禁止沿用旧图。只改列表标题而 Hook 未变时，不需要重出封面。

### 🔴 双比例尺寸与 fallback（v3.35.0；v1.0.2 grok 修正；v1.0.4 比例修正）
- 竖版 3:4：size 用 `1152x1536`（**`1024x1536` 是 2:3，不是 3:4**）；接口不认再退 `1024x1536`
- 横版 4:3：size 优先 `1536x1152`，接口不认再 `1536x1024`
- **grok-imagine-image（2924762）**：`1536x1152` 全拒，4:3 **直接用 `1536x1024`**，不要先打一发必失败的 1152；竖版只出 `1024x1536`（2:3 兜底）。
- 生成完成必须验证文件数与尺寸：`vertical-3-4.png`（抖音/视频号/公众号）+ `horizontal-4-3.png`（B站/通用）缺一不可；正片尺寸 1152×1536 / 1536×1152（`overlay_cover_text.py` 自动 cover 裁切，底图比例不符也不变形）。

### 🔴 3:4 曾误记为 1024x1536；比例必须 PIL 实测（v1.0.4 / 2026-09-22，2924762）
用户实测打回 `post-to-img-vertical-poster.png (864, 1821)`（≈1:2.1）：根因是文档把 `1024x1536`（2:3）当 3:4，且 prompt 没写死画布比例，服务端自由发挥成长图。
**修复三件套**：① 真 3:4 = `1152x1536`；② prompt 必须含画布锁定句（`build_prompt.py` 现按 `--size` 自动生成「像素 W×H，宽高比严格 a:b」）；③ 验收用 PIL 实测宽高比——竖 ≈0.75 / 横 ≈1.3333，**比例不对即重出，禁止只看文件大小或目测**。
**实测（`_003` / ai.prism.uno / gpt-image-2）**：不认精确像素——请求 `1152x1536` 返回 1086×1448、请求 `1536x1152` 返回 1448×1086（等比 0.943×）；**有锁句则比例严格正确，像素缩水可接受**。

### 🔴 grok-imagine-image 三坑（v1.0.2 / 2026-09-21，2924762）
主端点 `gpt-image-2` 在余额 &lt; $1 时报「预扣费额度失败」整批挂。切 `settings.json` 备用 `GEN_IMG_*_001`（elysiver + grok-imagine-image）后可出图。**禁止**在日志打印 Key；用完恢复主配置。
1. quality **只认 low / medium**（`gen_images.sh` 禁止对 grok 硬编码 `high`）
2. 4:3 用 `1536x1024`（见上）
3. 封面 prompt 禁字仍会冒英文/日文乱码 → **无字插画进 `covers/.scratch/`**，再用 `overlay_cover_text.py` + STHeiti 叠 `cover_text`

### 🔴 封面目录只留两张正片（v1.0.2 / 2026-09-22）
`covers/` 根目录只许 `vertical-3-4.png` + `horizontal-4-3.png`。无字稿、重试稿（`*-notext.png`）一律 `covers/.scratch/`。2924762 曾把 4 张中间图堆在根目录，用户会问「为啥这么多封面」。`gen_images.sh` 对非正片路径自动改写到 `.scratch/`。

### 🔴 GEN_IMG 整批超时后必须续跑缺失文件（v3.11.0 / 2026-07-22）
批量生图被 Bash 10 分钟超时 kill（exit 143）时：
1. 立刻 `ls` 盘点每张图的 size，**>5KB 视为成功**
2. **只补缺失文件**，禁止无条件重跑已有图
3. 场景图与封面可拆成多条 Bash 单独跑

### 🔴 GEN_IMG 多端点与日志安全（v3.10.0 / 2026-07-21）
1. 从 settings.env 组装 endpoint 列表（`''`, `_001`, `_002`…），逐张生成、已有跳过
2. 单张 max-time 90–180s；整批超时按张数放大或拆批
3. 日志只打印 `set/empty/len`，**禁止打印 key 前缀**（安全策略会拦）

### 🔴 封面文字糊掉 → 本地 Pillow 兜底（v3.19.0 / 2026-08-21）
API 出图但中文日期/品牌名糊掉、错字、变形时——封面文字必须像素级准确，直接用 Pillow 本地叠字：底图 + 渐变蒙版 + 本地字体（`STHeiti Medium.ttc` / `Arial Unicode.ttf`）。日期必须**水平居中**（`dx=(tw-dw)//2`），生成后 `Read` 视觉校验，不居中即重出。API 恢复后切回 API，本地图是兜底非默认。

### 🟡 竖封面必须带日期与品牌（v3.7.0 / 2026-07-18）
新闻流水线竖封面失败时用场景图回退会被用户打回（「上面没日期」）。**帖子成片**封面文字源是 `cover_text` 两行，不强制印日期/报刊名；禁止无字或乱码封面当正片。

### 🔴 帖子内容图必须先于视频流程（v1.0.3；v1.0.4 比例修正 / 2026-09-22）
整帖手账信息图和「两行封面 / 分镜场景图」是三种图。先按 `post-to-img`（kawaii-journal，参考 `generated-images/post-to-img/20260921_2931081/`）出：
- `posters/post-to-img-horizontal-poster.png`（4:3，`1536x1152`）
- `posters/post-to-img-vertical-poster.png`（3:4，`1152x1536`；**`1024x1536` 是 2:3，不要用**）
提示词用 `build_prompt.py --orientation`（画布锁定句自动写入，见上条）。竖版写明禁止三栏并排。两张 **PIL 实测比例（竖 ≈0.75 / 横 ≈1.3333）且 `Read` 视觉校验通过之前，禁止场景生图、TTS、合成**。信息图文字在画面里（gpt-image-2 能排中文）；不要用封面叠字脚本去贴整张信息图。schema 放 `posters/infographic.json`，不要覆盖 `content.json`。

### 🔴 脚本/生图/封面必须对照 合规检查.md（v1.0.2）
禁止词汇、脚本审核清单、平台合规审查、合规检查清单见 skill 根目录 `合规检查.md`。结果落盘 `{slug}/review-checklist.md`。硬规则：不出现帖子来源；称呼全部「道友+名字」；不画写实儿童/虐婴；不把 factory 的「佬友→大家」套到本产品。

## 二、TTS 配音

### 🔴 key 全失效时直接走 edge-tts，不要逐个试（v3.36.0 / 2026-09-18，坑 210）
连续多期同一鉴权错误（`Invalid API Key` / 401 / 403）说明是账号侧失效而非端点抖动，逐个端点重试纯属浪费。post-to-video **默认就是 edge-tts**，无此问题；edge-tts 本身连续可用、音色稳定、无配额、无 Key。

### 🔴 旧音频残留导致整体 desync（v3.20.0 / 2026-08-23 W33 实测）
重跑 TTS 或换期前，`voiceover/scene*.wav` 若是上期残留，atempo 的 SKIP 启发式（`out duration < raw*0.95` 视为已加速）会误判「已加速」直接保留旧音频 → 成片音画/字幕整体错位（W35 用户报 3 次）。
**修复链（必须按序，缺一步仍 desync）**：
1. 归档旧音频到 `.stale_archive/`（用 `shutil.move`；**`rm` 会被自动权限判为不可逆删除而拒绝**）
2. 重新合成 + atempo，覆盖写入
3. ffprobe 实测全部新 wav 时长
4. 重算字幕
5. 重渲染
6. whisper 抽 3–4 个边界点验证字幕与真实发音时刻一致（误差 <200ms）

### 🔴 TTS 必须串行（TTS 并发冲突坑）
并行调用 TTS 会因临时文件竞争（`mktemp: mkstemp failed: File exists`）静默失败不生成音频。**必须逐场景串行**，每个等上一个完成。

### 🔴 TTS 网关 503 退避（v3.9.0 / 2026-07-20）
`gateway_error` / 503 时指数退避（5s→15s→30s，最多 3–5 次）；**禁止**把空 wav / 半截音频当成功——每场景校验文件大小与时长；日志禁打印 key。

### 🟡 edge-tts 工程细节
- edge-tts 原生输出 MP3，必须 `ffmpeg -acodec pcm_s16le -ar 24000 -ac 1` 转 WAV（24kHz PCM16 单声道）才能进字幕/合成流程
- `atempo=1.4` 加速可显著缩短总时长（8 场景实测 112.13s）；加速后时长以 ffprobe 实测为准
- CLI 负数参数必须用 `=` 语法：`--rate=-50%`，写成 `--rate -50%` 会被解析成选项
- 推荐音色：`zh-CN-YunyangNeural`（云扬，男声新闻风）；克隆音色在短句/播报场景太机械，不推荐（v2.5.0）

### 🟡 脚本风格必须「说人话」（v2.5.0 / 2026-06-16）
默认口播偏播音腔会被观众打回。要求：不要「各位观众大家好」式开场；用「说白了」「这谁不爱」等口语；保留情绪不夸张；每段 ≤80 字。

## 三、字幕（演进史即血泪史）

### 🔴 字幕与音频不同步（v2.0.0 → v2.1.0 → v2.2.0 → v2.3.0 → v3.25.0 演进）
- **v2.0.0 FunASR 识别（已废弃）**：对专业术语识别极差（GPT→GDP、Claude Code→Claude coat），修正字典永远追不上新术语。**字幕内容必须用原始脚本文本，绝不依赖 ASR 文字。**
- **v2.1.0 纯字符比例（已废弃）**：内容准了但长句/多数字场景仍漂移。
- **v2.2.0 加权字符 + silencedetect（已废弃）**：加权系数是平均拟合，单句偏差大；silencedetect 只在「正好有停顿」时能吸附，中后段逐句累积漂移。
- **v2.3.0 whisper 词级时间戳（时间轴至今仍有效）**：`faster-whisper(word_timestamps=True)` + `SequenceMatcher` 强制对齐——**时间用音频真实发音时刻，不再做任何「估算每句时长」**；SequenceMatcher 容忍 ASR 个别错字。
- **v3.25.0 语义 group_caps 切行（当前默认）**：v2.3.0 的 `split_sentences` 把所有标点一视同仁 + 16 字硬墙，会切出 `延期；`（0.5s 闪行）、`终止Cursor`/`官方直连` 这种专名断裂。切行必须语义优先，whisper 只负责时间轴。

**切行物理下限**：

| 项 | 规则 |
|----|------|
| 目标行长 | 15–20 汉字 |
| `max_len` | 16：到此长度遇软标点才断 |
| `hard_max` | 20：允许略超以保住专名/动宾/正反并列 |
| 无合法切点 | 整句保留（可到 24–25），禁止按字符下标硬切 |
| 最短显示 | `merge_short_dwell(min_sec=1.0, max_len=20)`：<1s 并回上一行，**合并后仍 ≤20 字** |
| 视觉 | 单行字幕，不做双行长度平衡 |

**流程铁律**：先 `--dry-run` 人工扫禁切反例，再全量加载 whisper（`WhisperModel` 必须在 dry-run return 之后才 import）；帖内专名用 `--extra-word` 补 jieba 词典。

### 🔴 scenes 结构兼容 + 偏移按 wav 时长（v3.36.0 / 2026-09-18、09-19，坑 208）
1. scenes 三种写法都要兼容：`{"scenes":{1:"text"}}` / `{"scenes":["text"]}` / `{"scenes":[{"num":1,"text":"..."}]}`。dict 按 sid 排序；**list 保留声明顺序**（禁止把 `[1,2,3,4,6,5,7]` 这类重排静默还原）。
2. 场景偏移按 **wav 文件实际时长**（含片尾 pad 静音）累加，**不用** whisper 的 `info.duration`——VAD 裁掉尾部静音，用它推偏移会让后面每个场景字幕整体提前，越往后越明显。

### 🔴 用户名下划线会被读出来（2026-09-23，2931081，坑 223）
edge-tts 把 `chen_dragon` 读成「chen 下划线 dragon」。**口播文本里的用户名去掉 `_`，改成空格**（`道友chen dragon`）；`publish.json`、信息图海报的图内文字可以保留原名。改完必须重跑该场景 TTS，不能只改字幕。

### 🔴 字幕行宽门：字数过关也会被画幅裁（2026-09-23，2931081，坑 224）
`merge_short_dwell` 原先合并上限 24 字，叠上 `group_caps` 的 `hard_max+4` 会拼出 26 字行。预检用 Pillow `textbbox` 报「行宽+48 = 995 ≤ 1080」就放行，成片在 seek 28s 把「道友mcga说，普通人都是这么过来的。必经之路。」切成「…必经之」。
1. 合并后的行 **≤20 字**（脚本已改）。短于 1s 但合并会超 20 字的行，**保留短行**，不要为了消闪行而把字裁出画面。
2. 预检数字不是验收。交付前必须抽帧 `Read`，抽点覆盖**最长的几条字幕**所在时刻，不只抽首帧和片尾。字幕被右边缘切掉即回 Step 6 重切，禁止只调字号蒙混。

### 🔴 重跑 TTS 会归档全部现有 wav（2026-09-23，2931081，坑 225）
`gen_tts_edge.py` 启动即把 `voiceover/scene*.wav` 移进 `.stale_archive/`。口播还没定稿就跑，等于把好的配音清掉。
1. 只改了几个场景：`--only 6,7`。其余 wav 不动，`durations.json` 只更新这几个 id。
2. 不带 `--only` 重跑前，确认 `content.json` 的 voiceover 是终稿。误归档从 `.stale_archive/` 移回，不要再跑一遍 TTS 去「补」。

### 🔴 锚点/节奏超标用「重排播放顺序」修，不重写脚本（v3.36.0 / 2026-09-18，坑 209）
某场景需要落在特定时间位置时，交换 scenes 数组顺序即可（口播文本不动）。重排后**必须重跑字幕对齐**（顺序变了，偏移要重算）。

### 字体规范
系统字体：`"PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif`；字幕 40–48px、加粗、白字、黑色半透明底/黑边；**禁止商用字体**（方正、汉仪、造字工房等）。
Pillow 烧录必须画出圆角底，不能只描黑边：`rgba(0,0,0,0.75)` + padding `10px 24px` + radius 12，对齐 `news-pipeline/video-project/src/components/Subtitles.tsx`。v1.0.0 只画了白字黑边，v1.0.1 补上。

## 四、视频合成与校验

### 🔴 渲染前校验（v2.8.0）
**图片数 == 音频数 == 场景数**，三者不等先补齐；每个音频必须对应 1 张图，禁止无声场景。

### 🔴 时长必须来自 ffprobe 实测，禁止手填估算（2026-07-12 教训）
重跑 TTS 后必须同步刷新所有时长并重建字幕再渲染，否则画面按旧时长排布、字幕按新音频对齐，两条时间轴从中段开始逐渐错位。
**铁律：任何一次重跑 TTS（哪怕只改一个场景）→ 重新 ffprobe 全部音频 → 重算 captions → 重渲染。所有时间轴必须来自同一批音频。**

### 🔴 逐场景取整再求和（坑 209 同源）
分段时长逐段 `ceil(dur * fps)` 进位后再求和；若总时长只 ceil 一次，累计误差会切掉片尾。

### 🔴 渲染后校验
视频总时长必须 ≈ captions 末条 `endMs`（差 ≤0.5s）；抽首帧 + 场景切点帧 `Read` 视觉校验（防首屏残留上一期文字这类低级事故——v3.31.1 坑 189 曾把日期硬编码残留到下一期）。

### 🟡 合成后归档
视频渲完**立即**复制/确认到产出目录，不要等到交付阶段再找文件；注意渲染器实际输出目录可能与预期不同（ai-news-factory 曾踩「从 video-project/out 拷了旧文件」的坑）。

## 五、环境与其他

### 🔴 安全分类器不可用会阻塞非只读 Bash（v3.37.0 / 2026-09-20，坑 216）
分类器抖动时只读命令仍可过、非只读全被拦。对策：拆单条命令、间隔重试、改用 Write 落盘。

### 🔴 日志与 Key 安全
所有脚本日志禁止打印 API Key（含前缀）；配置文件从 `settings.json` env 读取，不在工具参数里硬编码 key（v3.12.0）。
