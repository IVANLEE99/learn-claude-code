# P2：每期加入 1 个专业解释

> 每期加入一个 15 秒左右的 AI 专业概念解释，用来增强内容的专业度，但不打断日报节奏。

---

## 一、推荐做法

采用 **日报中提取为主，概念库兜底**。

不要纯按“AI 所有概念从浅到难”机械排序，也不要完全临时从日报里随手抓。最佳方式是：

```text
日报驱动 + 概念库管理 + 难度节奏控制
```

核心原则：

- 当天日报里出现了关键技术概念，就优先解释这个概念。
- 当天日报没有明显技术点，就从概念库里选一个高频、基础、适合补充的概念。
- 每期只讲一个概念，15 秒内讲清“是什么 + 为什么重要”。
- 难度顺序只作为长期节奏，不作为每日强制顺序。

---

## 二、为什么不建议纯按难度排序

如果从 AI 全部概念里按“浅到难”排，会有三个问题：

1. **和当天新闻脱节**
   观众刚听完日报，突然插入一个无关概念，会像硬上课。

2. **不利于理解当期内容**
   专业解释最好解决观众刚听到的疑问，比如新闻提到 MoE，就顺手解释 MoE。

3. **容易降低内容节奏**
   日报类内容的优势是信息密度，专业解释应该是补充，不是另开一门课。

所以，专业解释应该服务于当天内容，而不是服务于一张概念学习路线图。

---

## 三、选题优先级

### 第一优先级：当天日报里反复出现、影响理解的概念

适合解释：

- MoE
- 上下文窗口
- Agent
- RAG
- API Key
- 模型蒸馏
- 开源模型
- 推理模型
- 多模态
- Benchmark

示例：

```text
今天日报提到某模型上下文窗口扩大到 100 万 token。
这一期就解释：为什么上下文窗口变大重要？
```

### 第二优先级：近期 AI 新闻高频出现的概念

如果当天新闻里没有特别明确的技术词，但近期频繁出现某类话题，可以选择这些概念。

示例：

```text
最近连续出现 API 泄露、模型滥用、开发者封号新闻。
这一期可以解释：API 密钥泄露怎么防？
```

### 第三优先级：从概念库中按浅到深补充

当日报内容偏商业、融资、政策、产品更新，没有明显技术概念时，从概念库中补一个。

---

## 四、概念库分层

### 入门层

适合前期多讲，帮助观众建立基础认知。

- Token 是什么
- 上下文窗口是什么
- API Key 是什么
- 开源模型是什么
- 模型幻觉是什么
- 多模态是什么
- Agent 是什么

### 进阶层

适合和模型发布、产品能力、开发工具新闻结合。

- MoE 是什么
- RAG 是什么
- Function Calling 是什么
- 推理模型是什么
- 模型蒸馏是什么
- Fine-tuning 是什么
- Embedding 是什么

### 偏专业层

适合在观众已经熟悉基础概念后逐步加入。

- RLHF 是什么
- 模型量化是什么
- Benchmark 为什么容易作弊
- 模型“降智”可能是什么原因
- 开源模型商业化意味着什么
- Agent 为什么会删库
- API 密钥泄露怎么防

---

## 五、15 秒解释模板

每条专业解释控制在 3 句话左右。

```text
今天的专业解释：什么是 {概念}？

{一句话定义}。
{一个简单类比或应用场景}。
{为什么它和今天这条新闻有关 / 为什么重要}。
```

更短的结构：

```text
概念是什么
+ 为什么重要
+ 和今天新闻的关系
```

---

## 六、示例脚本

### 什么是 MoE

```text
今天的专业解释：什么是 MoE？

MoE，全称 Mixture of Experts，可以理解成一个模型里有很多“专家模块”。
每次回答问题时，模型只调用其中一部分专家，所以能在参数很大的情况下控制计算成本。
这也是很多大模型能变强，但推理成本不爆炸的重要原因。
```

### 为什么上下文窗口变大重要

```text
今天的专业解释：为什么上下文窗口变大重要？

上下文窗口就是模型一次能读进去的信息量。
窗口越大，它越能同时处理长文档、多轮对话和复杂代码库。
所以当模型上下文变大，本质上是在提升它处理复杂任务的上限。
```

### API 密钥泄露怎么防

```text
今天的专业解释：API 密钥泄露怎么防？

API Key 可以理解成你调用 AI 服务的密码，泄露后别人可能直接刷你的额度。
最基本的做法是不要写进前端代码，也不要提交到 GitHub。
更稳妥的是放在服务端环境变量里，并定期轮换密钥。
```

### Agent 为什么会删库

```text
今天的专业解释：Agent 为什么会删库？

Agent 不只是聊天，它会调用工具、执行命令，甚至改文件。
如果权限给得太大、目标描述不清，它可能把“清理数据”理解成删除真实数据库。
所以 Agent 必须配权限边界、确认机制和可回滚方案。
```

### 为什么模型会“降智”

```text
今天的专业解释：为什么模型会“降智”？

模型“降智”通常不是突然变笨，而是系统提示词、安全策略、路由模型或推理预算变了。
同一个入口背后，可能会根据成本和流量切到不同模型。
所以用户感知到的能力下降，未必只来自模型本身。
```

### 编程模型评测为什么容易作弊

```text
今天的专业解释：编程模型评测为什么容易作弊？

很多编程评测题是公开的，模型训练时可能已经见过类似题目。
如果只看跑分，就分不清它是真会写代码，还是记住了答案。
所以更可靠的评测要看新题、真实项目和长链路任务。
```

### 开源模型商业化意味着什么

```text
今天的专业解释：开源模型商业化意味着什么？

开源模型不等于免费做慈善，它通常是用开放权重扩大生态和开发者采用率。
商业化可能来自云服务、企业部署、API、工具链和授权。
所以开源模型的竞争，不只是模型能力，也是谁能把生态变成收入。
```

## 七、执行流程

每期制作时按这个顺序做：

1. 先从当天日报中标出所有 AI 技术概念。
2. 选一个最影响理解、最适合 15 秒讲清的概念。
3. 如果没有合适概念，就从概念库入门层或近期热点中选一个。
4. 写成 3 句话，不扩展成长科普。
5. 记录本期讲过的概念，避免短期重复。

---

## 八、结论

专业解释不要做成固定课程表，而要做成日报内容的“顺手补充”。

最终策略：

```text
优先解释日报里出现的概念；
没有合适概念时，用概念库兜底；
长期用难度分层控制节奏。
```
