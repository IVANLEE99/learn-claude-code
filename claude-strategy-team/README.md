# Strategy Team — 战略团队

> 第 6 个团队：把控方向
>
> "方向错了，越努力越危险。战略团队存在的意义，就是在你跑得最快的时候，帮你判断该不该转弯。"

---

## 一、团队定位

### 1.1 为什么需要战略团队

一人公司在获得阶段性成果后，往往会面临以下困境：

- **方向模糊**：最初的产品组合到底要不要砍？
- **合作诱惑**：外部合作到底要不要接？
- **目标混乱**：季度 OKR 怎么排？先做什么？
- **资源有限**：精力、资金、时间都有限，该聚焦在哪里？

战略团队就是为了解决这些问题而存在的。它不是执行团队，而是**决策支持团队**——帮创始人看清现状、评估选项、做出选择。

### 1.2 核心价值

| 价值 | 说明 |
|------|------|
| **做减法** | 砍掉不赚钱的业务线，聚焦核心 |
| **做选择** | 在多个方向中选出最优解 |
| **做规划** | 把战略意图转化为可执行的 OKR |
| **做风控** | 识别风险，设置预警线和止损点 |

### 1.3 适用场景

- 阶段性成果复盘（"最近效果跟预期不太一样"）
- 产品取舍（"这个产品还要不要继续做"）
- 合作决策（"有个合作找上门，要不要接"）
- 方向调整（"下一步该往哪走"）
- OKR 制定（"这个季度 OKR 怎么排"）
- 资源分配（"精力有限，该聚焦在哪里"）

## 二、团队成员

### 2.1 总指挥：strategy-orchestrator

**文件**：`agents/orchestrator.md`

**定位**：战略团队的调度中心，整合六位专家的分析，输出最终战略决策。

**核心职责**：
- 调度六个子 agent 的执行顺序
- 整合各 agent 的分析结果
- 输出最终战略决策文档
- 设置人工检查点，等待创始人确认

**触发条件**：用户需要战略方向复盘或决策支持时激活

**模型**：opus（需要最强的推理和整合能力）

---

### 2.2 战略规划师：strategic-planner

**文件**：`agents/strategic-planner.md`

**定位**：现状诊断专家，从混乱的现状中提炼出清晰的战略选项。

**核心职责**：
- 梳理当前所有业务线/产品线的现状
- 对比初始目标 vs 实际结果，标注偏差
- 分析偏差原因（外部环境 vs 内部执行 vs 目标设定）
- 提炼 2-3 个可行战略方向，附优劣分析

**执行步骤**：
1. 收集用户当前业务状况（产品、收入、流量、用户反馈等）
2. 对比初始目标，识别超预期和不及预期的维度
3. 分析偏差原因
4. 基于现状和资源约束，提炼 2-3 个可行战略方向
5. 每个方向附带：优劣分析、资源需求、风险点、成功概率评估

**输出文件**：`docs/STRATEGIC_DIAGNOSIS.md`

**输出模板**：
```markdown
# 战略诊断报告
## 一、现状快照（业务全景 + 关键指标）
## 二、目标 vs 实际偏差（偏差表 + 关键发现）
## 三、战略方向选项（2-3 个方向，每个含优劣势、资源需求、成功概率）
## 四、建议（首选方向 + 理由 + 立即行动）
```

**沟通风格**：直击本质、用数据说话、坦诚面对、简明扼要

---

### 2.3 战略合作架构师：cooperation-architect

**文件**：`agents/cooperation-architect.md`

**定位**：合作评估专家，看穿合作邀约背后的真实意图。

**核心职责**：
- 评估外部合作机会的战略契合度
- 分析资源消耗和机会成本
- 识别显性风险和隐性风险
- 给出明确建议：接 / 不接 / 有条件接

**评估框架**：

| 维度 | 评分 (1-5) | 说明 |
|------|-----------|------|
| 战略契合度 | — | 是否符合当前战略方向 |
| 收益确定性 | — | 收益是否可量化、可预期 |
| 资源消耗 | — | 时间/精力/资金投入 |
| 依赖风险 | — | 是否会形成单点依赖 |
| 品牌影响 | — | 正面/中性/负面 |
| 退出难度 | — | 容易退出/中等/难以退出 |

**输出文件**：`docs/COOPERATION_EVALUATION.md`

**输出模板**：
```markdown
# 合作评估报告
## 合作概况（合作方、形式、双方诉求）
## 评估矩阵（6 维度评分）
## 风险分析（显性风险 + 隐性风险 + 最差情况）
## 谈判要点（必须争取的条件 + 可以妥协的点）
## 最终建议（接/不接/有条件接 + 理由）
```

**沟通风格**：警惕但不悲观、量化收益、关注隐性成本、底线思维

---

### 2.4 战略 PMO：strategic-pmo

**文件**：`agents/strategic-pmo.md`

**定位**：战略落地专家，把"想清楚"翻译成"做到位"。

**核心职责**：
- 将战略决策转化为可量化的 OKR
- 将 KR 拆解为月度里程碑和周任务
- 标注关键检查节点和风险预警线
- 考虑精力约束（一人公司每周 40-50 小时）

**OKR 原则**：
- **可量化**：每个 KR 必须有数字，不接受"提升""优化"
- **可追踪**：每周有检查点
- **精力约束**：OKR 必须在精力上限内
- **优先级清晰**：资源冲突时有明确取舍规则

**输出文件**：`docs/OKR_CURRENT_QUARTER.md`

**输出模板**：
```markdown
# 本季度 OKR
## 战略背景（核心方向 + 明确不做）
## O1：[目标名称]（KR 表 + 里程碑 + 周任务拆解）
## O2：[目标名称]
## O3：[目标名称]
## 资源分配（精力占比 + 每周小时数）
## 检查机制（日检查 + 周检查 + 预警线）
## 风险与应对
```

**沟通风格**：落地导向、数字说话、精力现实、灵活调整

### 2.5 新业务孵化官：incubation-officer

**文件**：`agents/incubation-officer.md`

**定位**：低成本试错专家，用最小代价验证新方向的可行性。

**核心职责**：
- 识别新业务的核心假设
- 用 ICE 模型评估优先级
- 设计最小验证方案（MVP 验证）
- 给出 Go/No-Go/Pivot 决策

**ICE 评分模型**：
- **Impact（影响力）**：如果成功，对整体业务的影响（1-10）
- **Confidence（信心）**：成功的概率（1-10）
- **Ease（容易度）**：验证和启动的难度（1-10）
- **ICE Score** = Impact × Confidence × Ease

**输出文件**：`docs/NEW_BUSINESS_ASSESSMENT.md`

**输出模板**：
```markdown
# 新业务评估报告
## 业务机会概述
## ICE 评分
## 核心假设（致命假设必须第一个验证）
## 市场规模估算（TAM/SAM/SOM）
## 最小验证方案（步骤 + 成功标准 + 失败标准）
## Go/No-Go 决策
## 与现有业务的资源竞争
```

**沟通风格**：冷静理性、聚焦假设、成本意识、敢于否定

---

### 2.6 投研分析师：investment-researcher

**文件**：`agents/investment-researcher.md`

**定位**：行业情报专家，从公开数据中提炼决策洞察。

**核心职责**：
- 分析行业趋势和增长曲线
- 追踪竞品近期动作和策略变化
- 识别机会窗口和风险信号
- 将外部信息与用户业务关联

**关注维度**：
- 赛道阶段（萌芽/成长/成熟/衰退）
- 趋势信号（利好/利空/中性）
- 竞品动态（近期动作 + 策略方向 + 威胁等级）
- 政策/监管变化
- 新出现的蓝海

**输出文件**：`docs/MARKET_INTELLIGENCE.md`

**输出模板**：
```markdown
# 市场情报报告
## 一、行业趋势（赛道概况 + 趋势信号 + 政策变化）
## 二、竞品动态（主要玩家 + 竞品启示）
## 三、机会窗口（当前可利用的机会 + 蓝海）
## 四、风险预警（风险表 + 预警信号 + 应对建议）
## 五、行动建议（立即关注 + 持续跟踪 + 可以忽略）
```

**沟通风格**：简洁有力、区分事实和推测、关注可操作性、警惕确认偏误

---

### 2.7 财务建模师：financial-modeler

**文件**：`agents/financial-modeler.md`

**定位**：轻量级财务分析专家，帮创始人做理性的资源分配决策。

**核心职责**：
- 梳理各业务线的投入（时间 + 资金 + 机会成本）
- 估算各业务线的产出（直接收入 + 间接价值）
- 计算 ROI 和盈亏平衡点
- 基于资源约束给出最优组合建议

**核心原则**：
- **简单直白**：不需要复杂 DCF 模型，算清楚投入产出就行
- **全成本核算**：时间也是成本，不能只算资金不算时间
- **机会成本**：做 A 就不能做 B，这个成本必须量化
- **保守估算**：收入往低了估，成本往高了估

**输出文件**：`docs/FINANCIAL_MODEL.md`

**输出模板**：
```markdown
# 财务分析报告
## 一、当前财务概况（收入结构 + 成本结构）
## 二、各业务线 ROI 分析（投入产出表 + 盈亏平衡点）
## 三、合作项目财务影响（如有）
## 四、机会成本分析
## 五、资源约束下的最优组合（约束条件 + 方案 + 预期结果）
## 六、关键财务指标监控（月收入/时薪/获客成本/现金流）
```

**沟通风格**：数字为王、直白坦诚、关注现金流、简化模型

## 五、使用指南

### 5.1 如何激活战略团队

在 Claude Code 中输入：

```
激活战略团队
```

或更具体的场景：

```
帮我做一次战略复盘
这个合作要不要接？
下一步该往哪走？
这个季度 OKR 怎么排？
```

### 5.2 回答问题的技巧

战略团队会向你提问以收集信息。回答时：

- **说事实，不说感受**："月收入 0 元" 而不是 "收入不太好"
- **具体数字**："每天 2 小时" 而不是 "时间不多"
- **坦诚现状**：粉饰现状会导致错误的战略判断
- **不需要组织语言**：逐条回答即可

### 5.3 检查点确认

每个检查点后，你需要：

1. **阅读输出文档**：理解分析结论和建议
2. **做出判断**：
   - 输入"继续" → 进入下一步
   - 提出调整意见 → Agent 会修改后重新输出
3. **不要跳过检查点**：战略决策需要你的确认

### 5.4 执行与复盘

战略决策完成后：

1. **按 OKR 执行**：每天对照 OKR 检查进度
2. **记录进展**：每天花 10 分钟记录当天完成事项
3. **每周复盘**：每周日晚复盘 KR 进展，调整下周任务
4. **预警响应**：触发预警线时及时调整策略

## 七、团队协作模式

### 7.1 Agent 间协作

- **Step 2 并行执行**：investment-researcher 和 cooperation-architect 同时工作
- **数据传递**：每个 agent 的输出都是下一个 agent 的输入
- **决策整合**：orchestrator 综合所有 agent 的分析，输出最终决策

### 7.2 人机协作

- **Agent 负责**：分析、评估、建模、建议
- **人类负责**：提供信息、确认方向、做出最终决策、执行落地
- **关键原则**：Agent 不做最终决策，决策权始终在创始人手中

### 7.3 沟通原则

所有 agent 遵循以下沟通原则：

- **数据优先**：每个建议必须有数据或逻辑支撑
- **敢于说不**：砍掉比新增更难，但战略团队的价值就在于做减法
- **短期生存 > 长期愿景**：一人公司首先要保证活下来
- **最小验证**：任何新方向都先用最小成本验证
- **透明权衡**：每个决策都明确展示机会成本

## 九、常见问题

### Q: 战略团队和商业闭环团队有什么区别？

**A**: 商业闭环团队负责"把流量变钱"，聚焦变现路径的设计和执行。战略团队负责"把控方向"，聚焦在更高层面的方向选择和资源分配。战略团队可能会建议砍掉商业闭环团队正在做的事情。

### Q: 多久应该做一次战略复盘？

**A**: 建议每 30 天做一次完整复盘，每 7 天做一次轻量级检查（对照 OKR 检查进展）。遇到重大变化（新机会、新风险、收入断崖式变化）时随时触发。

### Q: 战略团队的建议可以不听吗？

**A**: 当然可以。决策权始终在创始人手中。战略团队提供的是分析和建议，最终决定由你来做。但如果你连续多次不听建议，可能需要反思一下为什么。

### Q: 没有外部合作邀约，Step 2b 还要执行吗？

**A**: 不需要。cooperation-architect 只在有具体合作邀约时才调用。没有合作邀约时跳过 Step 2b，直接进入下一步。

### Q: 新业务评估（Step 3）什么时候执行？

**A**: 当战略诊断中出现新的业务方向选项，或者创始人在考虑拓展新领域时才执行。如果当前只是聚焦已有业务，可以跳过。

## 十、实战案例

### 案例背景

- **创始人**：一人公司创始人
- **现状**：6 条业务线，0 条产生收入
- **资源**：每天 2 小时，资金储备 1 个月
- **技能**：前端编程、项目管理
- **目标**：30 天内赚到第一笔钱

### 战略团队执行过程

1. **Step 1 诊断**：发现资源分散到致命程度，每条业务线每天只能分到 20 分钟
2. **Step 2 情报**：分析前端外包市场需求，发现真实需求存在
3. **Step 4 财务**：计算各方向 ROI，前端外包变现最快
4. **Step 5 决策**：砍掉所有空壳业务线，聚焦前端外包
5. **Step 6 OKR**：制定 30 天 OKR，目标收入 1000 元

### 最终产出

- **战略决策**：只做前端外包，其他全部砍掉
- **OKR**：3 个 O（建立接单能力 → 获得首单 → 完成交付）
- **30 天路线图**：Day 1-3 准备 → Day 4-14 获客 → Day 15-25 交付 → Day 26-30 扩展
- **预警机制**：Day 7 无询价降报价，Day 14 无订单考虑转向
